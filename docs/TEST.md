## 2. 测试范围 / 不测什么

- 覆盖：匿名统计的上报与落库、看板登录与锁定、看板各块数据的口径与页态，接口层与页面层都测。
- 覆盖：新游戏上架、斗罗换版，以及游玩时的存档提示与外部链接。
- 覆盖：http 下的存档与旅客编号搬到 https，老玩家不算新旅客。
- 覆盖：重写版对齐旧版的商店、搜索、详情、游戏库、存档码、旧地址与亮暗色（TC-STORE-*），旧单文件游戏的平台接口与存档（TC-LEGACY-*）。

- 启动(本地)：在项目根依次执行
  - `npm ci`
  - `printf 'KANBAN_PASSWORD=local-test-pass\nKANBAN_SECRET=local-secret-for-tests\n' > .dev.vars`（文件已在 `.gitignore`）
  - `npm run build`（产物在 `dist/`，是 Worker 的静态资源目录；改了平台代码要重新构建）
  - `npx wrangler d1 migrations apply shoota-metrics --local`
  - `npx wrangler dev --port 8812 --test-scheduled`（`--test-scheduled` 打开 `/__scheduled`，用来手动触发每天的定时任务）
  - 跑自动化用例：`npx playwright test`。8812 上没有服务时，它按 `playwright.config.ts` 的 webServer 自己执行上面最后三步；已经有服务就直接用。
- 本地跑旧版 dd731d6（源自缺陷用例修复前的那一轮）：旧版起在 8811，与重写版的 8812 可以同时开着
  - `rm -rf /tmp/shoota-old && mkdir -p /tmp/shoota-old && git archive dd731d6 | tar -x -C /tmp/shoota-old`
  - 在 `/tmp/shoota-old` 里写同样的 `.dev.vars`，再执行 `npx -y wrangler@4.151.1 d1 migrations apply shoota-metrics --local` 与 `npx -y wrangler@4.151.1 dev --port 8811`
  - 回到重写版目录执行 `E2E_PORT=8811 npx playwright test e2e/defects.spec.ts`：`E2E_PORT` 换掉 `e2e/lib/base.ts` 里的被测地址，Playwright 发现 8811 已有服务就直接测旧版
  - 跑完停掉旧版、删掉 `/tmp/shoota-old`
- 真机（TC-PLAY-008、TC-PLAY-009、TC-PLAY-010、TC-PLAY-011、TC-PLAY-020）：
  - 电脑上按「启动(本地)」起服务，另开一个终端执行 `cloudflared tunnel --url http://localhost:8812`（免费临时隧道，不用登录），手机打开它打印的 `https://<随机名>.trycloudflare.com`

  - 云存档的编号摘要：`printf %s <saveId> | shasum -a 256`，三张云端表都按这个摘要（`sid` 列）找行
  - 造多少天没同步的云存档：`UPDATE cloud_accounts SET seen_day = date('now','+8 hours','-366 days') WHERE sid = '<编号摘要>'`
  - 触发到期删除任务：`curl "http://localhost:8812/__scheduled?cron=0+20+*+*+*"`
  - 用 curl 调云存档接口：开通 `curl -s -X POST http://localhost:8812/api/cloud/account -H 'authorization: Save <32 位小写十六进制>' -H 'content-type: application/json' -d '{"code":"<16 位恢复码>"}'`；推送 `curl -s -X POST http://localhost:8812/api/cloud/sync -H 'authorization: Save <同上>' -H 'content-type: application/json' -d '{"have":{},"haveMeta":0,"push":[{"g":"yike","base":0,"enc":"json","body":"{\"yikezhicha.v2\":\"...\"}","bytes":<body 的字节数>,"s":300,"last":<毫秒时间>,"status":"","at":<毫秒时间>}]}'`；恢复码只能用 `0-9`、`A-H`、`J`、`K`、`M`、`N`、`P-T`、`V-Z` 这 32 个字符
- 本机数据构造：在平台同源的页面里执行（先打开一次平台首页），`e2e/lib/storage.ts` 有现成函数
  - 平台元数据 `localStorage['changju.meta.v1']`：本机玩家 `local`，各游戏累计秒数、最近游玩、成就、愿望单、成就定义都在里面；旧版写法见 `oldMeta`
  - 游戏存档：IndexedDB `changju` 第 1 版的 `kv` 库，键 `local|<游戏>`，值是这款游戏假 localStorage 的全部内容（键到字符串）；一克之差第 5 关的存档见 `YIKE_LEVEL5`
  - 撤销槽：同一个库的键 `undo:<游戏>`，值 `{save, stat, at, why}`
  - 云存档本机状态 `localStorage['changju.cloud.v1']`；悬浮按钮位置、已提示旋转与微信引导时间在 `localStorage['changju.ui.v1']`
  - 旧版格式的 CJ1 存档码：`'CJ1' + base64(gzip(JSON))`，JSON 为 `{v:1, at, saves, stats, wish, achDefs}`，与旧版导出的格式相同；用 Node 的 `zlib.gzipSync` 生成
- 弱网与卡住（`e2e/lib/proxy.ts`）：在本机起一个中转，浏览器只连它，它再转给 8812；页面与 Service Worker 的请求都经过它
  - 弱网：每个请求先等 400 毫秒，所有响应共用一条 50 KB/s 的链路
  - 压缩：上游没压缩的文本响应，中转按浏览器接受的编码压缩后再限速，和线上边缘一样（线上返回 `content-encoding: br`）；不压缩时薯光 3.08 MB 在 50 KB/s 下光下载就要 62 秒
  - 游戏文件（`/g/<游戏>-<摘要>` 与 `/games/<游戏>`）的模式：照常转发；不回（一直不回首字节）；第一次不回；每次卡住（发一半后停住不动）；第一次卡住；摘要地址 404；404；500
  - 中转记下每次游戏文件请求与 `/api/*` 上报的正文，用例据此数请求、读启动上报
  - 用中转的用例关掉 Service Worker（Playwright 上下文 `serviceWorkers: 'block'`），免得缓存里的游戏文件绕过模式；弱网首开与再开（TC-LAUNCH-009、TC-LAUNCH-010）不关
- 注入脚本（`e2e/lib/faults.ts`，用 Playwright 的 `addInitScript` 装进页面与游戏 iframe）：开关都在平台页面的 `window.__faults` 上，默认全关，用例里用 `setFaults` 改
  - 存档库卡住与报错：包住 `indexedDB.open` 与只读事务，开关为「卡住」时永远不回调，为「报错」时回调错误；读写事务照常，平台若把空存档写回会真的写进去
  - 丢掉就绪信号：平台页面收到旧运行层的 boot-ready 与 SDK 的 ready 时不交给平台的监听，其余消息照常
  - 记下全屏与方向锁定：包住 `requestFullscreen` 与 `screen.orientation.lock`，记下调用、目标元素与是否在用户点击里；可以让它们返回拒绝
  - 记下页面内消息：记下平台页面收到的、以及同源改写游戏页收到的 `ns` 为 shoota 与旧运行层的消息，读 `window.__msgs`
- 打开环境：UA 定义在 `e2e/lib/viewports.ts`：安卓手机 Chrome、安卓平板 Chrome、iPhone Safari、安卓微信。主屏幕应用（display-mode standalone）模拟不了，只在真机测
- 安全区：CDP `Emulation.setSafeAreaInsetsOverride`，例如 `{insets:{top:0,left:62,bottom:20,right:62}}`，视口 874×402
- 核心区占比（`e2e/lib/core-area.ts`，测量方法沿用 2026-10-22 旧版测量脚本）：每款先按脚本里登记的步骤进到主界面，再在游戏 iframe 里找出贴边的固定栏与主滚动区，核心区 = 游戏区扣掉上下左右固定栏后的矩形，占比 = 核心区面积 ÷ 视口面积；改写后的游戏按 GameShell 的 `data-shell` 标记取核心区。Google 字体请求直接拦掉，开减弱动态效果。Safari 可见区按 393×659 与 734×343 两个视口量，用 iPhone Safari UA，整屏占比再乘可见区面积 ÷ 屏幕面积
- 页面标记：用例按下面这几处认界面，改动时同步改 `e2e/lib/ui.ts`
  - 悬浮按钮的小点：存档写入、小点亮着的 2 秒里，悬浮按钮带 `data-dot="on"`
  - GameShell：根、信息区、核心区、侧栏、底栏分别标 `data-shell="root"`、`header`、`core`、`aside`、`footer`；信息区收起时带 `data-collapsed`，展开按钮带 `aria-expanded`
  - 可读名：悬浮按钮与游戏面板都叫「游戏菜单」，面板与旋转提示的关掉按钮叫「关闭」；载入页进度条带 `aria-valuenow` 与 `aria-valuemax`；游戏 iframe 的 title 是游戏名
- 模拟 http 与 https 两个地址（TC-027～TC-029、TC-031）：Playwright 把 `http://shoota.ai/*` 与 `https://shoota.ai/*` 的请求都转给 http://localhost:8812。浏览器里它们仍是两个来源，各有一份本地存储，与线上一样。浏览器启动时加 `--no-proxy-server` 与 `--host-resolver-rules=MAP shoota.ai 127.0.0.1`，没被转走的请求连不到线上。
- Playwright 启动 Chromium 系浏览器时默认关掉 `HttpsUpgrades`，模拟的是不自动升级 https 的浏览器（存档会留在 http 下的那类）。脚本自己传 `--disable-features` 时会盖掉 Playwright 默认的那一串，要把 `HttpsUpgrades` 一起写上，否则 http 下的搬家页会被浏览器改成 https。
- 工具：Edge 浏览器（Playwright，`channel: 'msedge'`，每条用例独立的浏览器上下文）、curl、wrangler d1 execute、真机用 cloudflared。线上直接请求接口时用 curl 或浏览器，Python 默认 User-Agent 会被 Cloudflare 浏览器完整性检查拦下，返回 403 与错误码 1010。

- 走查（步骤表带「截图键」的用例，做法照 test-doc 的 flow-walkthrough.md）：只在本地跑，脚本在 `e2e/tour/`，运行输出在项目根 `.tour-out/<本轮编号>/`
  - 起跑前确认 `git check-ignore -q .tour-out` 成功（输出目录不入库），`docs/tour/tour.json` 存在：`repos` 写仓别名到相对项目根的路径，本仓是 `{"changju": "."}`，`seed` 写展示种子的版本
  - 一轮的顺序：`TOUR_RUN=<本轮编号> node e2e/tour/reset.ts` → `TOUR_RUN=<本轮编号> TOUR_PASS=1 npx playwright test -c e2e/tour/tour.config.ts` → 再复位 → 同一条命令换成 `TOUR_PASS=2` → 再复位 → `TOUR_RUN=<本轮编号> node e2e/tour/gate.ts --publish`
  - 复位只删本轮时间窗内开通的云存档（三张云端表按 `sid`），时间窗起点在第一次复位时记进 `.tour-out/<本轮编号>/window`，输出复位前后各表的行数；统计表与启动表不用删：走查浏览器都带 `sk_staff=1`，上报不写库
  - 走查浏览器：浅色、减弱动态效果、关掉 Service Worker；页面与游戏 iframe 里的 `Math.random` 与 `crypto.getRandomValues` 按走查名固定种子，两遍生成同样的编号与恢复码
  - 截图只拍视口，手机缩到宽 720、电脑缩到宽 1100，`cwebp -q 70`；页面上的时分与「10月22日」这类日期自动登记成动态区域
  - 确定性门：`gate.ts` 把两遍的图在两遍登记的动态区域上都涂黑，再用 `magick compare -metric AE -fuzz 0.5%` 数差异像素，不超过全图像素的 0.01%（1100×688 的图上限 75）算通过；没通过的键不发布，`gate.ts` 以非零退出
  - 发布：通过的键从第 2 遍复制到 `docs/tour/shots/<截图键>.webp`，并替换 `docs/tour/shots.json` 里这些键的条目；本机要有 `cwebp` 与 ImageMagick 7（`magick`）
  - 登记完删掉 `.tour-out/<本轮编号>/`

## 5. 回归策略

- **全量轮**：首次成稿、重写版集成后的第一轮、看板或上报接口改版、数据表结构变更。
- **局部轮**（受影响用例 + 全部冒烟级）：单一改动。受影响用例用 design-doc 的 `impact.mjs <DESIGN.md> <ID> --test docs/TEST.md` 从改动的 `FLOW-*`、`REQ-*`、`INV-*` 反查。只改平台外壳（游戏页布局、悬浮按钮、面板）时另加 TC-PLAY-017 复测核心区占比。受影响链路有走查用例（截图键以该 FLOW-ID 开头）时一并跑，按 §3「走查」跑两遍、过确定性门后发布截图。影响面不确定时升级为全量轮。
- **复测轮**（上轮失败用例 + 全部冒烟级）：修复失败项之后。
- **源自缺陷的修复前一轮**：TC-LAUNCH-001、TC-PLAY-015、TC-PLAY-016 各在 §3「本地跑旧版」上跑一轮，范围写 `局部(<该 TC>)`，结果应为失败，失败分别落在第 2 步、第 1 步、第 1 步；重写版集成后的复测轮承接这三轮。
- **人工收口轮**（仅上轮「待人工」用例）：AI 轮之后由人工按 §3「真机」补测 TC-PLAY-008、TC-PLAY-009、TC-PLAY-010、TC-PLAY-011、TC-PLAY-020。
- **改写游戏**：目录里一克之差的 runtime 改成 play 之前，TC-SDK-001～TC-SDK-005 与走查 TC-PLAY-023 登记为阻塞；改成 play 的那次发布跑一轮局部，范围含这六条与 TC-PLAY-017。
- **线上冒烟轮**：首次上线后必跑 `TC-008`、`TC-010`、`TC-016`、`TC-STORE-001`；此后改动统计、看板或平台页面时再跑。
